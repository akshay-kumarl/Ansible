--limit 

In Ansible, --limit is a command-line option used with ansible-playbook (and other Ansible commands) to restrict execution to a subset of hosts from your inventory, even if the playbook targets a larger group.

ansible-playbook playbook.yml --limit <host-pattern>

1. Run on a single host
ansible-playbook site.yml --limit serv1
ansible-playbook site.yml --limit "srv1,srv2"


Why use --limit?
✅ Test changes on a single server before rolling them out.
✅ Perform maintenance on specific hosts.
✅ Retry failed hosts.
✅ Reduce execution time during debugging.


===================================================================

--tags

--tags is an Ansible command-line option that allows you to run only the tasks that have specific tags. It's useful when you don't want to execute an entire playbook.

ansible-playbook playbook.yml --tags <tag_name>

ansible-playbook -i /opt/inventory  httpd_setup.yaml --tags=copy_index

===================================
--skilp-tags

--skip-tags is an Ansible command-line option that tells Ansible to skip tasks that have the specified tag(s) while running all other tasks.

ansible-playbook playbook.yml --skip-tags <tag_name>

ansible-playbook -i /opt/inventory  httpd_setup.yaml --skip-tags=copy_index

ANSIBLE HANDLERS 

Ansible handlers are special tasks that run only when notified by another task. They are mainly used to restart, reload, or perform actions only if a change has occurred, making playbooks more efficient.

Why do we need handlers?

Without handlers, a service might restart every time the playbook runs, even when nothing has changed.

cat 2-httpd_handlers.yaml

---
- name: Install and Configure Apache HTTP Server
  hosts: all
  become: yes

  tasks:
    - name: Install httpd
      yum:
        name: httpd
        state: present

    - name: Start and enable httpd service  ## systemctl start httpd && systemctl enable httpd 
      service:
        name: httpd
        state: started
        enabled: yes

    - name: Deploy index.html
      copy:
        src: /opt/index.html
        dest: /var/www/html/index.html
      notify: Restart httpd
      tags: copy_index


    - name: httpd service staus
      shell: systemctl status httpd
      register: status_register
      tags: status

    - name: Disply status of register variable
      debug: 
        var: status_register.stdout
      tags: status

  handlers:

    - name: Restart httpd
      service:
        name: httpd
        state: restarted

====================================================================

Without Variables:

--------------------------------------------------

  become: yes

  tasks:

      name: httpd
      state: present

you need to edit the playbook.

====================================================================

Copy Module

    Copies file exactly as it is.

    No variable replacement.


Example

    src: file.txt

    dest: /tmp/


------------------------------------

Template Module

    Copies file

    Replaces variables first.


Example

template:

    src: file.j2

    dest: /tmp/

WHAT IS DYNAMIC INVENTORY?
--------------------------------------------------

    Dynamic Inventory allows Ansible to
    automatically discover hosts at runtime.

    Instead of manually adding servers to
    inventory.ini, Ansible fetches server
    information from cloud providers like AWS.

    Inventory is generated dynamically.


--------------------------------------------------
WHY DO WE NEED DYNAMIC INVENTORY?
--------------------------------------------------

Problem with Static Inventory

    inventory.ini

        Web1
        Web2
        DB1

Suppose AWS Auto Scaling launches:

    Web3
    Web4

Need to manually update inventory.ini ❌


Dynamic Inventory

    Automatically detects new EC2 instances.

    No manual updates required. ✅

    Automatically fetches running EC2 instances ✅

ANSIBLE FORKS 
====================================================================

--------------------------------------------------
WHAT ARE FORKS?
--------------------------------------------------

Forks determine how many managed hosts
Ansible can connect to and execute tasks on
at the same time (in parallel).

Default:

    5 forks

Meaning:

    By default, Ansible can execute a task
    simultaneously on 5 servers.


====================================================================
WHY DO WE NEED FORKS?
====================================================================

Suppose you have:

    100 Linux servers

Task:

    Install Nginx

Without parallel execution:

    Server1
      ↓
    Server2
      ↓
    Server3
      ↓
    ...
      ↓
    Server100

Very slow ❌


With Forks = 10

    Server1      Server6

    Server2      Server7

    Server3      Server8

    Server4      Server9

    Server5      Server10

All execute simultaneously ✅


====================================================================
DEFAULT VALUE
====================================================================

Default forks:

    5

Meaning:

If you have

20 servers

Ansible works like:

Batch 1

    5 Servers

↓

Batch 2

    5 Servers

↓

Batch 3

    5 Servers

↓

Batch 4

    5 Servers

====================================================================

Method 1

Command Line

ansible-playbook site.yml --forks 20

Method 2

forks = 20

ANSIBLE VAULT
====================================================================

--------------------------------------------------
WHAT IS ANSIBLE VAULT?
--------------------------------------------------

Ansible Vault is a security feature used
to encrypt sensitive information.

Examples:

    • Passwords
    • API Keys
    • AWS Access Keys
    • Secret Keys
    • Database Passwords
    • SSL Certificates

Encrypted data can only be viewed
using the correct Vault Password.


====================================================================
WHY DO WE NEED ANSIBLE VAULT?
====================================================================

Problem:

Suppose your playbook contains

------------------------------------

db_password: admin123

aws_secret_key: ABCXYZ123

------------------------------------

If stored in GitHub,

Anyone can see the passwords ❌


Solution

Encrypt the file using
Ansible Vault.

Now the file looks like

------------------------------------

$ANSIBLE_VAULT;1.1;AES256

6634656534...

------------------------------------

No one can read it without
the vault password.


====================================================================
REAL-TIME USE CASE
====================================================================

Company uses GitHub.

Repository contains

Playbooks

↓

Variables

↓

Database Password

↓

AWS Credentials

Instead of storing them
as plain text,

Encrypt them using
Ansible Vault.


====================================================================
HOW ANSIBLE VAULT WORKS
====================================================================

Plain Text Variables

        ↓

ansible-vault encrypt

        ↓

Encrypted File

        ↓

Git Repository

        ↓

During Playbook Execution

Provide Vault Password

        ↓

Ansible decrypts automatically


====================================================================
COMMON VAULT COMMANDS
====================================================================

--------------------------------------------------
1. CREATE ENCRYPTED FILE
--------------------------------------------------

ansible-vault create secrets.yml

You will be asked

Vault Password:

Confirm Vault Password:

Now edit the file.


--------------------------------------------------
2. VIEW ENCRYPTED FILE
--------------------------------------------------

ansible-vault view secrets.yml


--------------------------------------------------
3. EDIT ENCRYPTED FILE
--------------------------------------------------

ansible-vault edit secrets.yml


--------------------------------------------------
4. ENCRYPT EXISTING FILE
--------------------------------------------------

ansible-vault encrypt secrets.yml


--------------------------------------------------
5. DECRYPT FILE
--------------------------------------------------

ansible-vault decrypt secrets.yml


--------------------------------------------------
6. CHANGE VAULT PASSWORD
--------------------------------------------------

ansible-vault rekey secrets.yml


====================================================================
EXAMPLE
====================================================================

Create

secrets.yml

Contains

------------------------------------

db_user: admin

db_password: MyPassword123

------------------------------------

Encrypt

ansible-vault encrypt secrets.yml


Now

Nobody can read the file.

Run

Ansible asks

After entering the correct password,

Playbook executes successfully.

Useful for
